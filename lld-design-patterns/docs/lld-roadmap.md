# Low Level Design

## Personalized Curriculum Map: Low-Level System Design & Machine Coding

**Student Profile:**

* **Subject:** Low-Level System Design
* **Academic Goals:** Master LLD & machine coding for FAANG interviews.
* **Language:** Java
* **Grade Level:** Post-graduate in Computer Science

**Learning Approach:** The curriculum is designed for a post-graduate level, assuming a solid understanding of fundamental data structures and algorithms. The focus is on applying this knowledge to design robust, scalable, and maintainable systems under interview conditions.

---

| Learning Objective                                        | Resources                                                                                 | Activities                                                                                                                   | Assessments                                                                                            |
|-----------------------------------------------------------|-------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------|
| **Module 1: Foundations of Object-Oriented Design (OOD)** |                                                                                           |                                                                                                                              |                                                                                                        |
| **SOLID Principles**                                      | "Clean Architecture" by Robert C. Martin; GeeksforGeeks articles on SOLID.                | Refactor a small, poorly designed Java project to adhere to SOLID principles.                                                | Code review focusing on the correct application of each SOLID principle.                               |
| **Abstraction & Encapsulation**                           | "Head First Design Patterns" by O'Reilly; Java Documentation.                             | Design and implement a set of classes for a simple library system, focusing on hiding implementation details.                | Quiz on identifying violations of encapsulation and improper abstraction.                              |
| **Inheritance vs. Composition**                           | "Effective Java" by Joshua Bloch (Item 18); Online blogs and tutorials.                   | Implement a feature using both inheritance and composition, then analyze the trade-offs of each approach.                    | Whiteboard session explaining when to prefer composition over inheritance.                             |
| **Polymorphism**                                          | Baeldung articles on Java Polymorphism.                                                   | Create a program with a base class and several derived classes that exhibit polymorphic behavior.                            | Practical coding test requiring the use of polymorphism to solve a problem.                            |
| **Interfaces & Abstract Classes**                         | Official Java Tutorials on Interfaces and Abstract Classes.                               | Design an interface for a "Payable" service and implement it for different employee types (e.g., salaried, hourly).          | Code challenge: Choose and justify the use of an interface vs. an abstract class for a given scenario. |
| **Module 2: Core Design Patterns**                        |                                                                                           |                                                                                                                              |                                                                                                        |
| **Singleton Pattern**                                     | Refactoring.Guru, "Design Patterns: Elements of Reusable Object-Oriented Software" (GoF). | Implement a thread-safe Singleton logger class for a multi-threaded application.                                             | Code review to check for thread safety and lazy/eager initialization correctness.                      |
| **Factory Pattern (Simple, Method, Abstract)**            | SourceMaking tutorials, GeeksforGeeks on Factory patterns.                                | Create a notification service that uses a factory to generate different types of notifications (Email, SMS, Push).           | Machine coding problem to design a document creator using the appropriate factory pattern.             |
| **Builder Pattern**                                       | "Effective Java" (Item 2); Baeldung tutorial on the Builder pattern in Java.              | Build a complex `User` object with multiple optional and required fields using the Builder pattern.                          | Assessment of a code snippet to identify and fix issues in a poorly constructed complex object.        |
| **Prototype Pattern**                                     | DigitalOcean tutorials, Refactoring.Guru.                                                 | Implement a system to clone complex game objects (e.g., enemies with different states) using the Prototype pattern.          | Quiz on deep vs. shallow copying in the context of the Prototype pattern.                              |
| **Adapter Pattern**                                       | "Head First Design Patterns"; TutorialsPoint on Adapter Pattern.                          | Integrate a third-party analytics library with a different interface into an existing application using an Adapter.          | Practical task: Write an adapter to make an old legacy API compatible with a new system.               |
| **Decorator Pattern**                                     | Baeldung on Decorator Pattern in Java.                                                    | Design a coffee shop application where decorators add condiments (e.g., milk, sugar, caramel) to a base coffee.              | Code review of the coffee shop implementation for flexibility and adherence to the pattern.            |
| **Facade Pattern**                                        | JournalDev tutorials on Facade pattern.                                                   | Create a facade to simplify the API for a complex home automation system (lights, thermostat, security).                     | Design a simplified interface for a complex video conversion library.                                  |
| **Observer Pattern**                                      | "Head First Design Patterns"; GeeksforGeeks on Observer Pattern.                          | Implement a simple stock market application where multiple displays (Observers) update when a stock price (Subject) changes. | Whiteboard design of a system that requires event-driven updates.                                      |
| **Strategy Pattern**                                      | Refactoring.Guru, Baeldung on Strategy Pattern.                                           | Implement a payment processing system that supports multiple payment strategies (Credit Card, PayPal, Crypto).               | Mock interview question on how to add a new payment method to the system with minimal code changes.    |
| **Command Pattern**                                       | "Game Programming Patterns" by Robert Nystrom.                                            | Design a remote control for a smart home, where each button press is a command object that can be executed and undone.       | Implement a simple text editor with undo/redo functionality using the Command pattern.                 |
| **Module 3: Machine Coding & Interview Skills**           |                                                                                           |                                                                                                                              |                                                                                                        |
| **Requirement Clarification**                             | "System Design Interview" by Alex Xu; YouTube mock interviews.                            | Practice asking clarifying questions on ambiguous problem statements from LeetCode or past interview questions.              | Mock interview session focused solely on the requirement-gathering phase.                              |
| **Class & Schema Design**                                 | "Grokking the Low Level Design Interview"; Relevant design case studies.                  | For a given problem (e.g., Parking Lot), create a detailed class diagram and define the relationships.                       | Review of the class diagram for completeness, normalization, and correctness.                          |
| **Writing Clean, Extensible Code**                        | "Clean Code" by Robert C. Martin.                                                         | Solve a machine coding problem, then refactor it for readability, modularity, and extensibility.                             | Peer code review based on the principles outlined in "Clean Code."                                     |
| **Error Handling & Edge Cases**                           | Online articles on robust error handling in Java.                                         | Augment a previous project to handle all possible edge cases and exceptions gracefully.                                      | Assessment of code for its robustness and handling of invalid inputs.                                  |
| **Unit Testing**                                          | JUnit 5 User Guide; Baeldung tutorials on JUnit and Mockito.                              | Write comprehensive unit tests for a machine coding solution, covering all major functionalities and edge cases.             | Code coverage report analysis and review of the test cases' quality.                                   |
| **Module 4: Classic LLD Problems & Case Studies**         |                                                                                           |                                                                                                                              |                                                                                                        |
| **Design a Parking Lot**                                  | LeetCode discussion forums; YouTube tutorials on this specific problem.                   | Full implementation of a Parking Lot system in Java, supporting different vehicle types, ticketing, and payment.             | Live mock interview session designing and coding a Parking Lot from scratch.                           |
| **Design a URL Shortener**                                | "Grokking the System Design Interview"; CodeKarle on YouTube.                             | Implement the low-level design for a URL shortening service, focusing on the data model and API.                             | Design review of the schema and class diagrams for the URL shortener.                                  |
| **Design a Caching System (LRU/LFU)**                     | GeeksforGeeks implementation of LRU Cache; Baeldung tutorials.                            | Implement a generic LRU (Least Recently Used) Cache from scratch using appropriate data structures.                          | Coding challenge to implement an LFU (Least Frequently Used) cache and explain its trade-offs vs. LRU. |
| **Design a Vending Machine**                              | Design Gurus blog; Javarevisited articles.                                                | Code a complete vending machine system, handling states, inventory, and transactions.                                        | End-to-end demonstration and code walkthrough of the vending machine solution.                         |
| **Design a Library Management System**                    | Common OOD interview questions repositories.                                              | Implement a library management system with features for book issuance, return, and fine calculation.                         | Mock interview focused on extensibility (e.g., "How would you add support for digital media?").        |
| **Design an Elevator System**                             | InterviewBit, LeetCode discussion forums.                                                 | Implement the logic for an elevator control system, managing requests and movement efficiently.                              | Whiteboard simulation of the elevator logic with multiple elevators and floors.                        |
| **Design a Chess or Tic-Tac-Toe Game**                    | YouTube tutorials on designing board games.                                               | Design and implement a Tic-Tac-Toe game, focusing on the game loop, state management, and rules engine.                      | Peer review and play-testing of the implemented game.                                                  |
| **Design a Splitwise-like Application**                   | System design case studies on expense-sharing apps.                                       | Implement the core logic for a cash-flow minimization and expense-sharing application.                                       | Code review focusing on the algorithm used for simplifying debts.                                      |
| **Module 5: Advanced Topics & Mock Interviews**           |                                                                                           |                                                                                                                              |                                                                                                        |
| **Concurrency in LLD**                                    | "Java Concurrency in Practice" by Brian Goetz.                                            | Refactor a single-threaded LLD solution (e.g., Logger) to be thread-safe.                                                    | Mock interview question involving the design of a concurrent system like a connection pool.            |
| **Full Mock Interview 1**                                 | Pramp, interviewing.io, or with peers.                                                    | A 60-minute mock interview simulating FAANG conditions, covering a standard LLD problem.                                     | Detailed, actionable feedback from the interviewer on design, coding, and communication.               |
| **Full Mock Interview 2**                                 | Pramp, interviewing.io, or with peers.                                                    | A second mock interview with a different, more complex problem.                                                              | Analysis of performance improvements compared to the first mock interview.                             |
| **Review and Refine**                                     | Personal notes and feedback from all assessments and mock interviews.                     | Identify weak areas based on feedback and revisit the relevant modules and resources.                                        | Self-assessment of progress and adjustment of the learning plan for the final stages of preparation.   |
